# 01 — Product overview

Level: **high**. Read first if you have never seen the product. Everything here is checked against the
code at `526cfba` (HEAD `cafcefd` adds only a Sheets fix and a hosting build). The rules themselves live in `docs/PLATFORM_STRUCTURE.md` (the contract); this file
explains them and points at the code.

## 1. What it is

**SmartBizz** (by DevMonks, formerly *SmartDine*) is a multi-tenant point-of-sale for Indian counters:
restaurants and four kinds of shop. One Flutter app (Android, iOS, Windows, web at `/pos/`) serves every
tenant; what each tenant sees is decided by its **licence** (`licenses/{orgId}` in Firestore).

Pieces:

| Piece | Where | What it does |
|---|---|---|
| Flutter app (till + admin console) | `lib/` | Billing, tables, kitchen, stock, settings; the platform admin console is the same app signed in as `MASTER_ADMIN` (`lib/main.dart` routes to `MasterAdminScreen`). |
| Control plane | Firebase project `smartdine-restaurant-pos` (Firestore; `.firebaserc`, `lib/main.dart`); hosting site `smartdine-pos` (`firebase.json`) | Organisations, users, licences, packages, plans, device registry, audit, `tenant_metrics` aggregates. |
| Server | `google_apps_script/Code.gs` (+ `firestore.gs`, `bcrypt.gs`) | Web app `/exec`: trials, sign-up e-mail codes, login token (`ISSUE_AUTH_TOKEN`), signed licence lease (`LICENSE_LEASE`), mail, Google Sheets ledger actions (`SAVE_BILL`, `CLOSE_DAY`, …). |
| Tenant data | The tenant owner's **own Google Drive** (one Sheet per store) or the device only (Offline) | Bills, products, stock, expenses. The platform receives only aggregates (`tenant_metrics`). |
| Marketing site | `hosting_public/` (generated by `tools/site/build_site.py` from `tools/site/site_data.py`) | Hub + one page per trade (`restaurants/`, `kirana/`, `supermarket/`, `pharmacy/`, `retail/`), register page. |
| Guest web ordering | `hosting_public/r/` (served at `/r` and `/m`, see `firebase.json` rewrites) | Restaurant QR menu / ordering. |

Brand vs data names: users see "SmartBizz"; data identifiers keep "smartdine" on purpose (Firebase project,
Drive folder `SmartDine_Menu_Images`, Android app id `com.devmonks.smartdine`, crypto salt). Do not rename them.

## 2. Who uses it

Roles are strings on the user record; `StaffRole` in `lib/core/rbac_permissions.dart` maps them
(`CASHIER`→billing, `CHEF`→kitchen, `CAPTAIN`→waiter; `CLIENT`/`STORE_ADMIN` read as owner).

| Person | Role key | Gets | Notes |
|---|---|---|---|
| Platform admin (DevMonks) | `MASTER_ADMIN` | Admin console (`lib/screens/dashboard/master_admin_screen.dart`); can open a tenant's POS in support view (Tenants → ▶). | Sign-in needs a server-side 2-step e-mail code. `Entitlements.platformAdmin` = everything on. |
| Tenant owner | `OWNER`, no `franchiseId` | Everything the licence allows, all stores. | Offline tier: the only user. |
| Store owner | `OWNER` with `franchiseId` | One store. Cannot create OWNERs or see other stores. | |
| Manager | `MANAGER` | Menu/products, staff, settings, analytics, expenses, stock. | Not on Offline. |
| Cashier / billing | `BILLING` | Billing, order/sales history, khata, tables (restaurant). | Not on Offline. |
| Waiter | `WAITER` | Tables & Waiter Pad. | Restaurant, Standard+, more than one device. |
| Kitchen | `KITCHEN` | Kitchen display (KDS). | Restaurant, Standard+, more than one device. |

Which roles a licence carries: `LicenseComposer.rolesFor(vertical, tier, maxDevices)`
(`lib/core/license_composer.dart`), mirrored by `rolesFor_` in Code.gs. Role names shown to users come from
`VerticalLabels` (`ownerRoleLabel`, `managerRoleLabel`, `billingRoleLabel`, `kitchenRoleLabel`,
`waiterRoleLabel`). Kitchen and waiter roles are hidden for shops (`StaffRoleExtension.allowedVerticalsFor`).

## 3. The five trades

A tenant has exactly one trade (`Verticals` in `lib/core/package_model.dart`): `restaurant`, `kirana`,
`supermarket`, `pharmacy`, `retail`. It is resolved only by `Verticals.resolve(vertical:, businessCategory:)`
(business category wins when it names a trade). Customer-pickable categories: `BusinessCategories`.

| Trade | Pickable category (`BusinessCategories`) | What it gets that others do not |
|---|---|---|
| restaurant | `Restaurant & Cafe` (plus other hospitality labels) | Running tabs (`dineInBilling`), tables & floor plan, reservations, kitchen tickets (KOT, `dualPrinting`), kitchen display, waiter ordering, online menu, QR table ordering, online ordering. Receipt licence label "FSSAI"; counterfoil "RESTAURANT COPY". |
| kirana | `Kirana / Grocery Store` | Barcode billing, customer khata (credit ledger), stock management; loose/weighed items and scale labels. Licence label "Trade Lic."; "STORE COPY". |
| supermarket | `Supermarket / Departmental Store` | Same shop set as kirana. |
| pharmacy | `Pharmacy / Medical Store` | Shop set, plus batches & expiry (FEFO; expired batches never sold, `StockService`), "Pharmacy invoice" starter slip (`StarterTemplates.pharmacyInvoice`), licence label "DL No.", wording "Medicines". |
| retail | `General Retail / Fashion / Electronics` | Shop set; product variants (size/colour) with per-variant stock. |

Shops never send items to a kitchen (`fast_qsr_billing_screen.dart`: `sendsToKitchen = _vl.isRestaurant && …`).
Trade wording (menu vs products, orders vs invoices, dine-in vs walk-in) comes from `VerticalLabels.of(vertical)`
(`lib/core/vertical_labels.dart`).

## 4. Tiers (packages) and limits

A **package** is a trade's features at a tier: 25 starters `<trade>_<tier>` (`PackageCatalog.starterId`,
`TenantPackage.starterFor`). A **plan** is validity only (name, days, price, cycle) — it never carries
features, limits or roles.

Limits: `TierLimits` in `lib/core/entitlements.dart` (Code.gs twin `TIER_LIMITS`).

| Tier (`PackageTier`) | Storage | Devices | Outlets | Users | Editable |
|---|---|---|---|---|---|
| Offline (`offline`) | This device only (`PURE_OFFLINE`) | 1 | 1 | 1 (owner) | Never |
| Basic (`basic`) | Client's own Google Drive (`CLIENTS_OWN_SHEETS`) | 2 | 1 | 3 | Admin override only |
| Standard (`standard`) | Own Drive | 5 | 1 | 10 | Admin override only |
| Premium (`premium`) | Own Drive | 10 | 3 | 25 | Admin override only |
| Enterprise (`enterprise`) | Own Drive | 20 (default) | 10 | 50 | Per client (`allowsCustomLimits`) |

Features per tier (from `PackageCatalog.featuresFor`; full per-key table in `docs/05_FEATURE_REFERENCE.md`):

| Tier | Restaurant | Shops |
|---|---|---|
| Offline | core + running tabs, tables, reservations, KOT printing, expenses, analytics | core + barcode billing, khata, stock (pharmacy: batches & expiry), expenses, analytics |
| Basic | + cloud ledger (own Drive) | + cloud ledger |
| Standard | + e-mail bills, kitchen display, waiter ordering | + e-mail bills |
| Premium | + online menu, QR ordering, online ordering, multiple outlets | + multiple stores |
| Enterprise | = Premium, custom limits | = Premium, custom limits |

"core" = the eight `CommercialTier.offlineBasic` keys: billing, counter till, menu/products, receipt printing,
store settings, shift & day-end, staff & roles, backup & restore. They are always on, even on an expired
licence.

**Add-ons**: any key that applies to the trade, is not in the package and that the storage mode and device count
allow (`PackageCatalog.addOnsFor`). Switched per client in the Feature Matrix and stored on the licence
(`addOns`, `featuresOff`).

Storage modes offered at onboarding: `PURE_OFFLINE` and `CLIENTS_OWN_SHEETS` only. `CLOUD_SYNC` is legacy.
Offline stores validate once online, then run 30 days offline on a signed lease (7 days for cloud modes;
`LicenseLease.offlineGraceDays` / `cloudGraceDays` in `lib/core/license_lease.dart`).

Wording rule (contract §7): never "100% local", "fully offline" or absolute guarantees. Approved sentences:
`PackageCatalog.driveNotice` and `PackageCatalog.offlineNotice`.
